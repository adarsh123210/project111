# Courier Management System

A local desktop application for managing courier branches, customers, parcel bookings, tracking, and reports. The interface is built with Tkinter and data is stored in SQLite.

## Run the application

From the project directory, run:

```powershell
python main.py
```

The application initializes the database and opens the login window. Python's Tkinter and SQLite modules are used by the application. Pillow is optional; it enables the login screen to load its JPEG artwork, and the screen falls back to a package icon if Pillow is unavailable. There is no dependency manifest in the project currently.

`run.bat` is present as a Windows launcher, but it contains a machine-specific working directory. Running `python main.py` from this project directory is the portable option.

## Application flow

1. `main.py` calls `database.initialize_database()` and starts `LoginWindow`.
2. `config.py` holds application settings, UI colors and fonts, and the database path. The SQLite file is resolved relative to the project.
3. `views/login_view.py` handles role selection, sign-in, and routes authenticated users to the appropriate portal.
4. `views/base_view.py` provides the shared application window, sidebar navigation, and scrollable table setup.
5. Role-specific screens call `models/db_models.py` for database operations. Shared validation and calculation helpers are in `utils/helpers.py`.

The only supported sign-in roles are **Admin** and **Staff**. Customer records remain parcel sender/receiver profiles, not login accounts. Existing courier records and parcel assignments remain in SQLite for data preservation, but courier login and screens are removed.

## Screen map

### Admin

Implemented in `views/admin/admin_views.py`:

- Dashboard and recent parcel activity
- Staff management
- Branch management
- Parcel oversight and status override
- Shipment tracking
- Transactions and delivery charge configuration
- User accounts
- Date-filtered reports with summary, transaction, and parcel views

### Staff

Implemented in `views/staff/staff_views.py`:

- Staff dashboard
- Customer directory
- Parcel booking and charge calculation
- Branch-to-branch transfer dispatch

Parcel tracking and checkpoint history are available to Admin and Staff.

## Database map

`database.py` creates the SQLite schema and seeds initial accounts and sample reference data. `courier_management.db` is the persistent local database; back it up before replacing or removing it.

- **users** — login names, password hashes, role, and active state
- **staff** — staff profiles linked to users
- **couriers** — retained legacy records; no courier login or screens
- **branches** — branch details and active state
- **customers** — sender and receiver contact/address profiles
- **parcels** — tracking number, sender/receiver, route, package details, legacy courier assignment, status, and charge
- **tracking_events** — parcel status history, location, remarks, and updater
- **branch_transfers** — parcel movement between branches
- **transactions** — parcel payment amounts and status
- **delivery_charges** — rates by parcel type and express multiplier
- **audit_log** — action and record history fields

`models/db_models.py` groups database operations for authentication and accounts, branches, staff, customers, charges, parcel booking and tracking, transfers, transactions, dashboards, and reports.

## Configuration and assets

- `config.py` defines `APP_NAME`, window sizes, theme colors, fonts, parcel/payment options, and `DB_PATH`.
- The login screen currently loads `international courier services near me.jpg` from the project root. Artwork files are also kept in `assets/`.
- `utils/helpers.py` contains password hashing, tracking-number generation, phone/email validation, clipboard support, and delivery-cost calculation.
